    Stage de 10 semaines au Club Robot de l'IUT de Saint-Dié. Conception et développement d'un système de supervision d'une serre connectée, accessible via une interface web.

    Stage — 23 février au 24 avril 2026

    Serre Connectée — Club Robot

    Le Club Robot de l'IUT de Saint-Dié-des-Vosges disposait d'une serre instrumentalisée mais sans interface unifiée pour en superviser l'état ni en piloter les actionneurs à distance. L'objectif du stage était de concevoir et développer de A à Z une application web complète reliant une interface moderne, une API Django REST, un Raspberry Pi et un Arduino contrôlant le matériel physique.

    Fonctionnalités réalisées

    • Visualisation temps réel des capteurs (température, humidité air/sol, luminosité, niveau d'eau)
    • Contrôle des actionneurs : toit (servomoteur), LEDs horticoles, pompe à eau
    • Mode autonome (Arduino seul) et mode manuel (contrôle utilisateur)
    • Représentation 3D interactive et synchronisée de la serre avec Three.js
    • Galerie de photos webcam associées aux données capteurs horodatées
    • Système d'authentification sécurisé avec expiration de session
    • Page de journalisation (logs) réservée à l'administrateur

    Architecture technique

    • Client web JavaScript — polling HTTP toutes les secondes sur /api/last/
    • API Django REST Framework — 14 routes HTTP (rendu HTML + endpoints JSON)
    • Base de données SQLite — 4 modèles : Serre, Usr, Logs, Photo
    • Raspberry Pi — intermédiaire entre le serveur et l'Arduino
    • Arduino — contrôle direct des capteurs et actionneurs physiques
    • IPC par fichier texte partagé /tmp/serre_cmds.txt

    Stack & outils

    • Django REST Framework (back-end Python)
    • Three.js ES6 (rendu 3D WebGL)
    • HTML / CSS / JavaScript natif (front-end)
    • Raspberry Pi + Arduino (embarqué)
    • Git / GitHub (contrôle de version)
    • VS Code (éditeur)

    Détail technique

    Flux de données & chaîne de commande

    Le système repose sur deux types de flux complémentaires. Le flux montant remonte les données des capteurs jusqu'à l'interface, tandis que le flux descendant transmet les commandes de l'utilisateur jusqu'aux actionneurs physiques.

    ARCHITECTURE Flux de données — Serre Connectée 
    ── Flux montant (capteurs → interface) ──────────────────────────
Arduino       collecte les données (temp, hum, lux, eau…)
   ↓          envoi JSON sur port série
Raspberry Pi  reçoit et transmet à l'API
   ↓
Django API    enregistre en base de données (modèle Serre)
   ↓
Client web    polling /api/last/ toutes les secondes → mise à jour DOM

── Flux descendant (utilisateur → actionneur) ───────────────────
Clic bouton   → fetch POST JS vers /api/toit/ | /api/led/ | /api/pompe/
   ↓          (protection CSRF via cookie csrftoken)
Django vue    → écrit la commande dans /tmp/serre_cmds.txt
              → crée une entrée dans le modèle Logs
   ↓
Processus série (manage.py) lit le fichier toutes les 100 ms
   ↓
Arduino       reçoit l'instruction → active l'actionneur physique
   ↓
Retour d'état dans le prochain cycle de polling (1–2 secondes)

    Réalisation principale

    Visualisation 3D avec Three.js

    La représentation 3D est la partie la plus stimulante du stage. La scène est entièrement construite de manière procédurale à partir de primitives Three.js, et se synchronise en temps réel avec l'état physique de la serre via des fonctions globales appelées à chaque cycle de rafraîchissement.

    Modélisation procédurale

    • Table texturée, sol, mur de fond et groupe serreGroup
    • Murs en verre transparent (opacity: 0.1, DoubleSide)
    • Toit mobile en BufferGeometry personnalisée
    • Plante : tige, fleur sphérique, pétales en ShapeGeometry Bézier
    • Tuyaux de pompe en TubeGeometry sur CatmullRomCurve3
    • Réservoir d'eau transparent + écran LCD simulé en CanvasTexture

    Synchronisation temps réel

    • setToitAngle() — rotation du toit par interpolation linéaire (* 0.05 par frame)
    • setLedIntensity() — deux SpotLight rouges à intensité 250 000 ou 0
    • setPompeState() — opacité des tuyaux intérieurs (eau visible ou non)
    • setEauStock() — scale.y du waterMesh proportionnel au volume réel
    • setLCDText() — redessine le canvas 2D + force needsUpdate = true

    Boucle d'animation

    • Pilotée par requestAnimationFrame + THREE.Clock
    • 30 gouttes d'eau en InstancedMesh (évite la création/destruction répétée)
    • Physique simple : gravité à −0,15, détection de collision avec le pot
    • Particules d'éclaboussure à l'impact
    • Interpolation fluide de la rotation du toit à chaque frame

    Difficultés rencontrées & solutions

    Trois défis techniques majeurs ont été identifiés et résolus au cours du stage.

    PROBLÈMES / SOLUTIONS Serre Connectée — Ethan STASSE 
    1. Synchronisation inter-processus (Django web ↔ processus série)
   Problème  : deux processus Django indépendants sans canal de communication
   Solution  : fichier texte partagé /tmp/serre_cmds.txt comme IPC
               → vidé en une seule opération avant lecture pour éviter les doublons
               → risque de condition de course atténué par open(CMD_FILE,"w").close()

2. Fuites mémoire GPU dans la galerie photo Three.js
   Problème  : chaque TextureLoader().load() alloue de la mémoire GPU non libérée
   Solution  : geometry.dispose() sur les anciennes géométries TextGeometry
               → référence à la texture courante (screenTexture) pour old.dispose()
               → paramètre ?t=Date.now() pour invalider le cache navigateur

3. Expiration de session — cohérence client / serveur
   Problème  : l'utilisateur restait sur le dashboard après expiration Django,
               les commandes échouaient silencieusement (redirection au lieu de JSON)
   Solution  : setTimeout côté client (3 600 s) pour redirection automatique
               → détection HTTP 401 + redirected dans refreshData()
               → double mécanisme : expiration client ET vérification serveur

    Analyse personnelle

    Retour sur le stage

    Ressources mobilisées

    J'ai mobilisé les cours de développement web, de bases de données et de programmation orientée objet. Three.js avait été abordé en cours, ce qui m'a permis de gagner du temps sur la prise en main. J'ai consulté la documentation officielle Django, Django REST Framework et Three.js, ainsi que des ressources complémentaires pour la communication série Python et la gestion mémoire GPU.

    Implication & autonomie

    Le travail a été organisé de manière très autonome, avec des points hebdomadaires avec M. PIERRE pour valider les réalisations et orienter la semaine suivante. J'ai géré seul l'ensemble du cycle : analyse des besoins, conception de l'architecture, développement, tests et correction de bugs.

    Points forts

    La représentation 3D synchronisée en temps réel est la réalisation dont je suis le plus fier — voir la serre prendre vie dans le navigateur et refléter l'état physique réel a été particulièrement stimulant. La gestion complète du projet en autonomie m'a aussi appris à structurer mon travail sur la durée.

    Points à améliorer

    Certaines documentations Three.js se sont révélées obsolètes ou incomplètes, ce qui m'a contraint à tâtonner et chercher par moi-même. Si c'était à refaire, j'anticiperais davantage les problèmes de mémoire GPU dès la conception et j'envisagerais Redis plutôt qu'un fichier texte pour l'IPC entre processus Django.

    Objectifs à venir

    Déployer l'application en HTTPS, implémenter des alertes automatiques en cas de dépassement de seuils critiques, ajouter des graphiques historiques des relevés. À plus long terme : remplacer le canal IPC par un bus Redis plus robuste et explorer le développement d'une application mobile complémentaire.

    Compétences acquises

    Maîtrise de Django REST Framework pour la conception d'une API robuste, communication série entre Raspberry Pi et Arduino, intégration de rendu 3D temps réel avec Three.js, conception d'une architecture multi-couches reliant matériel embarqué, back-end Python et front-end JavaScript. Gestion d'un projet technique complet en totale autonomie.
